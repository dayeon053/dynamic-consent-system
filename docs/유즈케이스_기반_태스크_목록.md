## Epic 1. 크롤링 봇 - 필수동의 및 선택동의 항목 자동 수집 (F1 / UC-04)

**목표:** 국내 주요 서비스 5~10개 기업의 개인정보처리방침을 매일 자동 수집하고, 전일 대비 변경을 감지하여 알림 플래그를 설정하는 파이프라인을 구축한다.

| # | 태스크명 | 설명 | 완료 기준 | 우선순위 |
| --- | --- | --- | --- | --- |
| 1-1 | 크롤링 대상 기업 선정 및 URL 목록 작성 | 초기 대상 5~10개 기업 확정, 각 기업의 개인정보처리방침 페이지 URL 수집 | 대상 기업 목록 + URL 표 노션 업로드 완료 | 상 |
| 1-2 | 크롤링 봇 기본 구조 설계 | 봇 전체 파이프라인 설계 (수집 → LLM 파싱 → 변수 매핑 → 위험도 산출 → DB 저장 → 변경 감지) | 파이프라인 플로우차트 또는 문서 완성 | 상 |
| 1-3 | 개인정보처리방침 웹 크롤링 구현 (1단계) | 대상 기업 약관 페이지에서 텍스트를 자동 수집하는 크롤러 구현 | 5개 기업 텍스트 수집 성공 확인 | 상 |
| 1-4 | LLM 파싱 모듈 구현 | 수집된 약관 텍스트에서 필수동의/선택동의 항목을 LLM으로 추출하는 모듈 구현 | 1개 기업 이상 필수/선택동의 항목 정상 파싱 확인 | 상 |
| 1-5 | 5대 변수 자동 매핑 로직 구현 | 파싱된 항목을 DS/ES/TF/PC/AI 5개 변수에 자동으로 매핑하는 로직 구현 | 5개 기업 전체 변수 매핑 결과 확인 | 상 |
| 1-6 | 전일 대비 약관 변경 감지 로직 구현 | 오늘 수집 텍스트와 DB 저장본 비교하여 변경 여부를 자동 감지하는 로직 구현 | 약관 변경 시 변경 감지 플래그 정상 설정 확인 | 상 |
| 1-7 | Spring Boot 스케줄러 연동 (1일 1회 자동 실행) | 매일 정해진 시간에 봇 파이프라인 전체가 자동 실행되도록 스케줄러 구현 | 스케줄러 실행 로그 확인, 수동 개입 없이 자동 동작 확인 | 상 |
| 1-8 | 회원가입 화면 캡처 + OCR 방식 구현 (2단계, 추후) | 봇 탐지 우회가 필요한 기업에 대해 회원가입 화면 캡처 + OCR로 항목 추출하는 방식 추가 구현 | OCR 텍스트 추출 결과 확인 (1개 기업 이상) | 하(추후) |
| 1-9 | 크롤링 대상 기업 관리 기능 구현 (UC-06, 관리자) | 관리자가 크롤링 대상 기업을 추가/삭제하고 테스트 크롤링을 실행할 수 있는 관리자 콘솔 구현 | 기업 URL 등록 → 테스트 크롤링 → 정상 수집 확인 흐름 동작 | 중 |
| 1-10 | LLM 출력 포맷 고정 및 파싱 예외 처리 구현 | LLM 응답을 특정 JSON 구조로 강제하고, 미사여구 포함이나 포맷 깨짐 등 파싱 에러 발생 시 재요청(Retry) 또는 에러 로그를 남기고 다음 프로세스로 넘어가는 예외 처리 로직 구현 | 다양한 입력 실패 케이스(잘못된 JSON, 빈 응답 등)에 대해 백엔드 서버가 다운(Crash)되지 않고 예외 로그를 남기는지 확인
포맷 오류 시 최대 2회 재요청(Retry) 후 실패 처리 흐름 검증 | 중 |

## Epic 2. 위험도 자동 산출 및 DB 저장 (F2)

**목표:** 봇 파이프라인 내에서 위험도 공식(Risk Score = DS + (ES × TF × PC × AI) × 2)을 자동 적용하여 기업별 개인 맞춤 위험도를 산출하고 날짜별로 누적 저장한다.

| # | 태스크명 | 설명 | 완료 기준 | 우선순위 |
| --- | --- | --- | --- | --- |
| 2-1 | 위험도 산출 공식 로직 구현 | Risk Score = DS + (ES × TF × PC × AI) × 2 공식을 코드로 구현 | 3개 기업 이상 위험도 정상 산출 확인 | 상 |
| 2-2 | 개인 맞춤 위험도 산출 로직 구현 | 필수동의 + 사용자가 실제 체크한 선택동의 기준으로 개인별 위험도를 산출하는 로직 구현 | 사용자별 선택동의 체크 현황에 따라 위험도 수치 변화 확인 | 상 |
| 2-3 | 위험도 5단계 등급 분류 로직 구현 | 산출된 점수를 매우 안전/안전/보통/위험/매우 위험 5단계로 분류하는 로직 구현 | 각 등급 경계값 정의 문서 완성 + 분류 정상 동작 확인 | 상 |
| 2-4 | DB 날짜별 누적 저장 구현 | 산출된 위험도 점수를 날짜별로 삭제 없이 누적 저장하는 DB 구조 및 저장 로직 구현 | 2일 이상 연속 저장 후 날짜별 조회 확인 | 중 |
| 2-5 | 선택동의 철회 시 위험도 실시간 반영 구현 | 사용자가 선택동의를 철회하면 위험도가 즉시 재산출되어 반영되는 로직 구현 | 선택동의 1개 해제 시 위험도 점수 변화 확인 | 상 |

| # | 태스크명 | 설명 | 완료 기준 | 우선순위 |
| --- | --- | --- | --- | --- |
| 3-1 | 앱 실행 감지 로직 구현 (UsageStatsManager / Accessibility) | UsageStatsManager 또는 Accessibility Service를 이용하여 대상 앱(카카오톡 등) 실행을 감지하는 로직 구현 | 카카오톡 실행 시 감지 로그 확인 | 상 |
| 3-2 | 패키지명-기업 매핑 테이블 구현 | 앱 패키지명([com.kakao.talk](http://com.kakao.talk) 등)과 DB 기업 정보를 연결하는 매핑 테이블 설계 및 구현 | 5개 기업 이상 패키지명 매핑 완료 | 상 |
| 3-3 | 오버레이 팝업 권한 처리 구현 | SYSTEM_ALERT_WINDOW 권한 요청 및 처리 로직 구현 | 권한 허용/거부 흐름 정상 동작 확인 | 상 |
| 3-4 | 오버레이 팝업 UI 구현 | 위험도 5단계 등급 텍스트 + 앱 내 상세보기 버튼만 표시하는 간결한 팝업 UI 구현 | 실제 카카오톡 화면 위에 팝업 표시 확인 | 상 |
| 3-5 | 팝업에서 기업 상세 화면으로 연결 구현 | 팝업의 상세보기 버튼 클릭 시 앱 내 해당 기업 상세 화면(위험도 탭)으로 이동하는 기능 구현 | 상세보기 버튼 클릭 → 기업 상세 화면 정상 진입 확인 | 중 |

| 4-3 | 위험기관리스트 화면 구현 | 개인 맞춤 위험도 높은 순으로 기업 목록을 표시하는 리스트 화면 구현 | 위험도 순 정렬 목록 정상 표시 확인 | 상 |
