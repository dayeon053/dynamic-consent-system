## **🤝 팀원 1(가현) ↔ 팀원 3(다연) 협업 방식 — 블로킹 방지 전략**

**핵심 원칙: JSON 포맷을 먼저 합의하고, 각자 병렬로 개발한다.**

가현과 다연이 서로 기다리지 않고 동시에 개발하려면, LLM이 최종적으로 뽑아줄 결과물의 생김새(JSON 구조)를 1단계 말에 미리 합의해야 함.

### **Step 1. 가현이 할 일 (1단계 말, 2단계 시작 전)**

가현은 LLM 프롬프트를 짜기 전에, 아래 샘플 JSON을 다연에게 공유함.
"LLM한테 이런 형태로 뽑아오게 만들 거야. 이 구조 기준으로 파싱 짜줘."

```json
{
  "company_name": "카카오톡",
  "variables": {
    "DS": 3,
    "ES": 2,
    "TF": 4,
    "PC": 1,
    "AI": 2
  },
  "summary": "약관 요약 내용..."
}
```

### **Step 2. 2단계에서 각자 병렬 개발**

| 가현 (인프라) | 다연 (데이터 가공) |
| --- | --- |
| 실제 카카오 약관 페이지 크롤링 | 위 샘플 JSON이 들어온다 가정하고 파싱 코드 작성 |
| LLM 프롬프트 작성 → 위 JSON 포맷으로 출력되도록 유도 | 파싱된 값을 DB에 저장하는 적재 로직 구현 |
| LLM 응답이 JSON 형태로 잘 나오는지 테스트 | LLM 응답이 JSON이 아닐 때 재시도하는 Retry 모듈 구현 |

### **Step 3. 3단계에서 연결**

가현의 실제 LLM 출력 → 다연의 파싱 모듈에 그대로 꽂으면 끝. 포맷을 미리 합의했기 때문에 수정 없이 바로 연결 가능.
